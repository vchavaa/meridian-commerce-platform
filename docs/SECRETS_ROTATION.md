# Secrets Rotation & History Audit

**Scope:** what to rotate, when, and how to confirm nothing sensitive remained in repo history.

## What this repo *should* contain

- No private keys, no API keys, no OAuth secrets, no DB passwords.
- No concrete GCP project IDs (`project_id` is a required Terraform input with no default; manifests use `PROJECT_ID_PLACEHOLDER` and are rendered by `scripts/apply_project_id.sh` or your templating tool of choice).
- No concrete admin emails. `ADMIN_ALLOWED_EMAILS` is left empty in the ConfigMap; operators supply via a Kustomize overlay or `envsubst`.

## Automatic sanity check before every commit

Install [`gitleaks`](https://github.com/zricethezav/gitleaks) and run:

```bash
gitleaks detect --source . --no-git -v
```

A pre-commit hook is recommended; this is left to the operator so the demo repo stays dependency-light.

## Rotate anything that ever hit a repo

If any of the below items were ever committed (even if later removed), rotate:

| Secret | Rotation path | Owner |
|---|---|---|
| CA private key | New CA in Secret Manager; dual-trust CAs during overlap; revoke old issuer | SRE |
| Partner client cert | Mint a new cert from the active CA; redistribute to partner; revoke old serial | SRE + partner integration |
| Public TLS server cert/key | New cert via Certificate Manager or cert-manager; swap Secret Manager version | SRE |
| GCP service account JSON key (never used in this repo) | `gcloud iam service-accounts keys delete` + create new; prefer Workload Identity | Security admin |
| Cloud SQL IAM DB user password | Rotate via `gcloud sql users set-password`; app uses IAM auth so this is only relevant for legacy flows | SRE |
| OIDC audience / client secrets | Create a new OAuth client; update `GOOGLE_OIDC_AUDIENCE`; delete old client after rollout | Security admin |
| Akamai origin secret (`x-akamai-origin-secret`) | Rotate `akamai_origin_secret` Terraform var; `terraform apply` publishes new Cloud Armor policy; update Akamai Property to send the new value | SRE + edge |
| Local admin bearer token (`LOCAL_ADMIN_TOKEN`) | Only used when `APP_ENV=local`; regenerated by `run-local.sh/.ps1` on every run | n/a (ephemeral) |

## Audit git history for leaked secrets

```bash
# Full-tree scan including deleted paths:
git log --all --full-history -p -- 'certs/*' \
  | grep -E 'BEGIN (RSA |EC |)PRIVATE KEY|-----BEGIN CERTIFICATE' \
  | head

# Scan with gitleaks across full history:
gitleaks detect --source . -v
```

If anything is found, follow the rotation table above **before** making the finding public.

## Terraform state is sensitive

The Cloud Armor policy published by `terraform/observability_security.tf` compares against the Akamai origin secret in its expression. Terraform state therefore contains the secret in plaintext:

- Use an encrypted remote backend (`gs://` with CMEK, or Terraform Cloud).
- Restrict `storage.objectViewer` on the state bucket to the smallest group possible.
- Enable object versioning on the state bucket; prune old versions when rotation is complete.
- Treat `terraform.tfstate*` as secrets — never check them into git.
